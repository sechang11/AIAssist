Where the model runs

Seven ways to generate the rewrites, with what each actually costs you as the number of people using it grows. Every figure is an estimate meant for choosing between options, not for a budget.

What the numbers assume.
  • One person does twenty remixes a day, so six hundred a month. Adjust everything proportionally.
  • One remix is roughly five hundred tokens in and five hundred to seven hundred fifty out.
  • Electricity at fifteen cents per kilowatt hour; a desktop with a GPU averaging a hundred watts.
  • Rented GPU at sixty cents an hour, which is a small card such as an L4 or A10G.
  • Provider prices move. Check them before committing; the gaps between tiers are the durable part.

The home row is electricity for the whole machine, not per user, which is why it does not move. It stops working long before a hundred people, not because of cost but because one consumer card serves a handful of requests at a time.

The seven, in detail

1 · Claude API

What the code does today. Best writing by a clear margin.

2.1c a remix · $13 per user each month

For

  • Best at the thing that matters: not changing what you promised
  • Already written and working
  • No infrastructure at all

Against

  • Cost grows with every user, forever
  • Private messages leave the phone
  • Needs a proxy before anyone else installs it

2 · A cheaper cloud model

Same shape, smaller model. Haiku, or an open model served by someone else.

0.02c to 0.43c a remix · 12c to $2.60 per user

For

  • Effectively free at the scale you are at
  • One-line change from what exists
  • No ops, no downloads, works on any phone

Against

  • Still an API bill, however small
  • Messages still leave the phone
  • Quality drop needs measuring, not assuming
Best for friends and family

3 · Your PC at home

Ollama on a machine you own, reached through a free tunnel.

~$11 a month in electricity, whoever uses it

For

  • No per-user cost at all
  • Runs a 7B to 14B model, far better than anything a phone fits
  • Nothing to download, works on any phone
  • An afternoon to set up
  • Swap models freely without shipping an update

Against

  • Your uptime is their uptime
  • Handful of simultaneous users, then it queues
  • You are exposing an endpoint and must lock it down
  • Cannot grow into a product

4 · Rented GPU, always on

The same thing in a datacentre.

~$430 a month before you have a single user

For

  • Real uptime and real bandwidth
  • Cheapest per call once traffic is heavy

Against

  • Costs more than the Claude API until you have hundreds of users
  • Fixed bill from day one
  • You now run servers

5 · Serverless GPU

Billed by the second, scales to zero.

Fractions of a cent per call, plus idle if kept warm

For

  • No bill when nobody is using it
  • Absorbs a spike without planning

Against

  • Cold starts can run tens of seconds, which kills this interaction
  • Avoiding that means paying to stay warm, which is option four
Best if it becomes a product

6 · On the phone

A quantised small model downloaded on first run.

Zero, at any number of users, forever

For

  • The only option whose bill does not grow when you succeed
  • Nothing leaves the phone, which is the strongest thing this app could say
  • Works on a plane, on the underground, with no signal
  • No servers, no keys, no proxy

Against

  • Several hundred megabytes to download before first use
  • Slowest of all, seconds not milliseconds
  • Weakest writing, needs constrained output and probably fine-tuning
  • Excludes older and cheaper phones, so you need a fallback anyway

7 · Everyone brings their own key

Each person pastes in their own API key.

Nothing, to you

For

  • Best possible writing at no cost to you
  • No infrastructure, no liability for their spend

Against

  • Asking a friend to open a developer account is a lot to ask
  • Realistically nobody outside software will do it
  • Storing other people's keys on a phone is its own problem

So which one

Me and a dozen friends, this month, free

Your PC at home

Ollama, a small Qwen, and a free Cloudflare tunnel with a shared token. Costs pocket change in electricity, runs a model several times larger than any phone fits, and you sideload the app rather than shipping it. Nothing else gets you this quality for nothing.

Strangers install it and I refuse a bill

On the phone

The only architecture where a thousand users costs the same as one. Pay for it in download size, latency and writing quality, and keep a device check with a graceful message for phones that cannot manage.

I want it good and a tiny bill is fine

A cheap hosted open model

Around a dollar a month for ten people. If the objection to an API was the price rather than the principle, this is worth a second look, because it removes every operational problem on this page for roughly nothing.

The decision is cheaper than it looks, because it is reversible. Everything on this page sits behind one interface, VariantGenerator. Swapping where the model runs touches one file and leaves the screens, the bubble and the tests alone.

So the sequence beats the choice. Stand up the home server this week, because it is the fastest path to a working app you can hand to someone, and it tells you the thing you actually need to know: whether a small open model can produce a usable grid at all. If it can, on-device becomes a port rather than a gamble. If it cannot, you have learned that for the price of an afternoon instead of a fortnight of Android work.
